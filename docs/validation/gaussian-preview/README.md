# 全局网格、局部原始像素窗口与高斯加速：实现与发布记录

本记录对应[PR #5 Spec](../../../discuss/20261113_gaussian_preview_optimization_spec.md)的实现，用户本地检查、PR审查和Astra high正文复审已通过；PR #5已于2026-11-14合并并发布。已承接此前的自动分组、预算诊断、斑宽控制与一次亮度适配；不是仅把536²粗图放大。科学输出仍为理想相对强度，B真实材料强弱与绝对计数继续暂缓。

## 使用与结果边界

4288²板的全局图现在是536²，每显示格几何范围为8×8 raw；其他自定义板保持512²，结果同时提供原始和显示尺寸。粗积分组仍按面积分配，不能恢复组内细节。全局标尺按每显示格信号，显式标记会话适配、手动设置或既有配置/初值。

打开“局部原始像素窗口”，点击全局图、选择HKL或拖动定位框。拖动不算，正常松手提交最新256×256 raw范围；显示利用面板内容宽度，板外以斜纹掩膜显示。局部强制stride=1，累加所有相交反射，选中的HKL只负责定位。运动中旧图标记过期，停止后重算固定raw窗口；它不跟踪HKL漂移。局部灰度按每原始像素，初值100，可显式“适配局部亮度一次”，之后跨窗口/姿态固定。

局部在窗口与反射支持及有限板面求交后才积分，不生成全幅后裁剪。默认独立预算仍为200000个反射-像素单元、2000000次求值；分配、访问、实际完成数分开报告，同时保留每反射尾界、误差尺度、求积误差与状态。全局失败不阻断局部；局部失败仍为unresolved，积分和标为null、部分和单列，不允许适配亮度或静默粗化。

高斯自动预览和局部窗口已启用平滑板面积分，窄峰或几何Jacobian难解析时逐格回退圆环算法；均匀球仍用原路径。全局“逐原始像素”及数值帧API默认仍使用圆环路径；数值候选需显式传 `gaussianQuadrature:'plane'`。当前自动stride规则保持不变，没有承诺全局stride<=8。

## 性能证据及限制

Node 24+ / Windows，保持默认预算；每方法先预热1次，再交替重复5次取中位墙钟耗时。下表为本机一次运行的诊断，不是浏览器响应时间承诺；原始计时和失败位于ignored `artifacts/gaussian-preview/benchmark.json`。

| 场景与相同计算网格 | σ_g / Å⁻¹ | 圆环中位ms | 板面中位ms | 解释 |
|---|---:|---:|---:|---|
| 实验室，全局自动分组 | .01 | 118.8 | 102.9 | 相同stride约1.15倍 |
| 对中，全局自动分组 | .01 | 153.4 | 109.0 | 相同stride约1.41倍 |
| 实验室，全局自动分组 | .03 | 248.5 | 199.6 | 相同stride约1.25倍 |
| 对中，全局自动分组 | .03 | 266.5 | 210.0 | 相同stride约1.27倍 |
| 实验室，128² raw局部 | .003 | 46.0 | 4.68 | 约9.8倍，均在默认预算完成 |
| 对中，128² raw局部 | .003 | 284.0 | 29.4 | 约9.6倍，均在默认预算完成 |

σ=.01/.03的局部候选中位约16 ms、212992次求值；原圆环在200万次默认预算失败。为数值参考显式给圆环2000万次预算后，逐像素和总量对照通过；这个扩展仅用于离线参考，不是提高生产默认预算，也未据此宣称速度比。σ=.05局部候选涉及约6.6–7.1万个反射-像素单元、约86–93万次求值，中位约56–59 ms。

局部128²不保证任意宽度/密集反射都完成。全局σ=.03/.05固定stride8在两条路径下都可能超预算；σ=.05全局自动分组仅约3–4%改善。窄核固定粗步长时新候选可能因保护/回退略慢，不能据局部收益宣称普遍大幅加速，故不调细当前自动stride启发式。

## 256²窗口扩展（2026-11-14）

用户本地试用后明确授权256×256 raw、显示利用面板宽度，保留松手计算及原预算。`LOCAL_SIZE=256`统一驱动定位矩形、canvas、标签和像素数组；拖动偏移及坐标终点按实际宽高推导。canvas宽度100%，保持256²数值缓冲及正方形，不因屏幕变化增加积分点。原39项性能矩阵的`local-128`已显式固定为128²历史基准，避免尺寸常数改变后仍以旧标签生成新尺寸结果。

同一σ=.03、98.0112 keV、(200)完整落板场景的浏览器实测（1次预热、5次中位）：峰居中128²为16.3 ms、212992求值、接收该反射约65.6%；192²为28.1 ms、479232求值、90.4%；256²为45.2 ms、851968求值、98.2%；384²为99.8 ms、1916928求值、99.98%。这些是数值积分耗时，不含绘图/输出整理，不承诺所有几何或重叠情况。当前256²默认仍为20万反射-像素、200万求值；窗口最多65536个有效raw像素，多反射会重复消耗，超限仍显示未完成。

本次尺寸增量的局部数值5项、typecheck和build已通过；两项Edge局部流程通过（26.8秒），包括256²宽高斯正信号、65536个完成单元、原200万次预算、非中心拖动抓取偏移、松手提交、预算失败/灰度拒绝、重叠、动停和桌面/390px满宽无溢出。Astra high增量评审PASS，无当前范围阻断项。5173已确认HTTP 200且实际canvas为256²、无Vite错误覆盖层，可刷新后本地检查。历史128²结果不冒称256²验证。

## 随显示亮度过滤自动HKL标签（2026-11-14）

每个反射的预览峰值灰度至少16/255才自动标注，随当前gray上限及display threshold变化；这是黑底显示经验下限，不是提峰/检出门。手动选中可保留定位标签，关闭HKL则全部隐藏。候选集、反射列表、原始信号和局部窗口均不删减。

峰值统计复用同一次`downsample`面积分配，以每tile的稀疏格累加，避免反射重叠时使用其他反射亮度，也不为每个HKL重建一张536²图。图像灰度与标签使用同一映射函数。单测覆盖对比度/显示阈值、缩图有无统计数值一致、重叠分离和板边/粗格；3项标签单测与5项局部单测、build/typecheck通过。3项Edge流程通过（13.4秒），验证灰度调暗后自动标签消失、强度和列表不变、手动选择/显示开关、阈值隐藏及恢复，并回归原三维工作流。

默认实验室σ=.03并适配亮度时，图上只保留8个标签，另48个低于亮度下限仍在列表中；截图为ignored `artifacts/gaussian-preview/hkl-visible-desktop.png`。本轮标签增量经Astra high只读复核PASS，无当前范围阻断项；算法/窗口既有评审不冒称覆盖该增量。
